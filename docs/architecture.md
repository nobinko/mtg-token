# 設計

このドキュメントは、MTG Token Finder の判断基準と実装境界をまとめます。使い方は [usage.md](usage.md)、巡回元の実測は [decklist-sources.md](decklist-sources.md)、変更履歴は [changelog.md](changelog.md) を参照してください。

## 設計思想

- バルクがエキスパンションごとに並んでいる前提で、まず探しやすさを優先する。
- 「トークンを出すカード」ではなく「バルクから抜く現物」を主役にする。
- 現行環境に関係ない古いデッキリストは混ぜない。
- フォーマットと大会日が決まったら、公式セット発売日または禁止改定から現環境開始日を先に確定する。
- 検索上限はページ数ではなく、デッキ/リスト数を主基準にする。
- メタ傾向は補助情報であり、現物準備の主情報は「出すカード」「必要現物」「採用元」に置く。
- トップメタ順位は検索サンプルの推定値と混ぜず、出典が公開する現在の集計として期間・母数・取得日時を明示する。
- 典型デッキは平均リストを合成せず、比較対象の中から実在する完全リストを選ぶ。

## 準備表と在庫の範囲

画面はリスト選択・大会条件・準備数・抜き出すセット・カード準備表の順に表示し、年表やメタ集計など補助情報は折りたたみます。参加者の網羅性、取得不足や照合失敗の警告は準備表の上にも表示します。

実検索の`buildBulkObjects`は`stockOnly: true`で印刷版を選びます。`stockTokenProduct`はトークンから親製品をたどり、途中を含めてtoken / expansion / coreのみを認めます。統率者セットが通常セットを親に持つ場合も除外します。紙・発売済み・通常フレームで同一Oracle IDと仕様の版だけを選び、発生源セットを優先。トークンの版にはModernの使用可否を適用しません。

通常セット版未確認の物理トークンは`NEEDS-PREPARATION`へ集約し、`stockStatus`は`available`・`not-found`・取得失敗の`unconfirmed`を区別します。元の印刷IDは仕様と再検索用に保持しますが、画像は表示せず日本語画像補完でも復活させません。汎用補助は`HELPERS`に集約します。準備チェックは従来の仕様キーで共有し、過去に別製品から準備した記録も有効です。別版APIは在庫対象だけを返し、特殊製品への代替は行いません。

## データフロー

大会の提出リストを受け取れる場合は通常の環境判定・巡回とは別の入口を使用します。`lib/tournament.js`が英語テキスト／CSV／JSONを正規化し、参加人数・失敗・重複を持つスナップショットを`.cache/tournaments/`（公開版ではR2）へ原子的に保存します。`POST /api/tournament`で取り込み／大会URLからの呼び出しを行い、`POST /api/token-cards`の`sourceMode: tournament`は保存済みの大会のみを集計します。フォーマット・大会日・取り込み日時がUI確認時と一致しなければ409で読み込み直しを要求します。

大会モードはScryfall collection APIへ提出カード名を75件ずつ送って直接照合し、環境候補キャッシュと他大会の巡回に依存しません。その後は既存の発生源照合・現物生成・全採用URLの保持・画像付きデッキ表示を共有します。採用率の母数は読み込めたリスト数、参加人数不明時は網羅性未確認です。UIの入口は`public/tournament-ui.js`、入力書式とMelee側の取得制限は[melee-tournaments.md](melee-tournaments.md)を参照してください。

```text
UI入力
  ↓
server.mjs（ローカル）/ worker.mjs（公開）→ app.mjs
  ↓
環境開始日を解決
  ↓
Scryfallから候補カード母集団を取得
  ↓
デッキリストソースをクロール
  ↓
デッキカード名を抽出
  ↓
デッキ内の候補カード言及を集計
  ↓
トークン/紋章/コピー/裏向き補助などの現物候補を生成
  ↓
検索結果を返す
  ↓
日本語名/日本語画像を後追い補完

MTGTop8フォーマットページ
  ↓
現在のトップメタ10を抽出
  ↓ ユーザーが1件を選択
表示中の実績期間から完全リストを最大8件取得
  ↓
枚数ベクトル間距離のmedoidとなる実在リストを表示
  ↓
Scryfall collection APIでカード種別・画像・両面情報を一括補完
  ↓
ブラウザ内の手動プレイテスト卓へ展開・デッキ別にローカル保存
```

## 巡回方針

巡回は「条件が決まってから」行います。汎用のデッキリスト一覧や記事ページから広く掘ると、フォーマット外・環境外の古いデッキが混ざるためです。

- MTGO公式は `/decklists` から `/decklist/{format}-...` 形式のリンクだけを辿り、`window.MTGO.decklists.data` JSONを読む。
- MTGTop8はフォーマットページからイベントページ、個別デッキページへ進む。
- magic.ggはフォーマット名がURLや `<deck-list format>` に現れる時だけ採用する。
- 晴れる屋はメタゲームページをアーキタイプ補助として読む。検索結果 `result` はAWS WAF challengeで本文が返らないため自動巡回しない。
- 記事・カバレージ系は日付フィルタが効かず古いデッキを拾うため、デフォルト巡回元にはしない。

ソースごとの現在の実測結果は [decklist-sources.md](decklist-sources.md) に残します。ソース側の制限は変わるため、デフォルト巡回元を変える前に再測定してください。

## 環境判定

配布後の更新は[環境データ更新の設計](environment-updates.md)を正とします。起動時に一度読み込む同梱JSONだけでなく、検証・保存済みの更新データを実行中に参照します。自動検知イベントは公式適用日の確認まで検索起点に使用しません。

単純な「直近N日」ではなく、現在の各フォーマット環境が始まった日から大会日までを対象にします。環境イベントは2系統を統合して解決します。

- **セット発売**: Scryfall `/sets` から自動生成（`lib/set-events.js`、24時間キャッシュ）。通常セット（expansion / core、紙）のみを全構築フォーマットの環境イベントとして扱います。未発売セットも含まれるため、発売日を過ぎた大会日を指定すると自動的に新環境起点になります。
- **禁止改定・ローテーション**: `data/environment-events.json`を初期値とし、更新ボタンで取得した履歴を優先。CI検知分は未確認として記録し、公式適用日確認後に利用します。

同じ日付・同種のイベントは手書き側を正とします。Scryfall に到達できない場合は期限切れキャッシュ→手書きイベントのみ、と段階的に縮退します。

検索APIは、環境開始日を解決できない場合、古いデッキを混ぜる代わりに検索を実行しません。

## デッキ抽出と失敗の扱い

カードリスト構造は見つかったがカード名を抽出できなかったデッキは、分類母集団から外します。抽出失敗デッキ数はサマリーに別表示します。

これにより、抽出に失敗したページを `Unknown` アーキタイプとして水増ししません。メタ傾向の合計は「カード名を抽出できた検索デッキ数」と一致します。

カード名の集合だけでなくメイン/サイド別の枚数行も保持します。トップメタの典型例候補はメイン60枚以上・サイド15枚以下を完全リストとみなし、各カードの枚数差を和集合の枚数で正規化した距離で総当たり比較します。平均距離が最小の候補（medoid）を返すため、表示されるのは常に出典に存在するデッキです。

トップメタの順位はMTGTop8の現在のフォーマットページから取得します。検索の大会日は過去メタの復元には使いません。典型リスト候補は、通常検索では大会日と今日の早い方までの該当環境、準備モードでは検索本体と同じ新セット導入前の実績期間に絞ります。未来の大会では未発生の実績を要求せず、実在する直前リストを準備用ベースラインと明示します。同率は出典の掲載順を維持します。

## ひとり回しの状態境界

ひとり回しはルールエンジンではなく、紙の盤面操作を記録するクライアント側の状態機械です。カード効果、適正な対象、マナ、優先権、勝敗、対戦相手の行動は判定しません。

- `public/goldfish.js` はDOMに依存せず、メイン／サイド、手札、土地／クリーチャー／その他の戦場レーン、墓地、追放、統率／相棒、各種プレイヤー値、カウンター、P/T、メモ、表裏、グループを不変更新する。
- 山札の末尾を一番上として扱う。通常のサーチは選んだカードを移動してからシャッフルし、「上からX枚」は順序を保持する。この2操作をUIでも明確に分離する。
- `public/goldfish-ui.js` はドラッグ＆ドロップ、同一レーン内の挿入位置、複数選択、ショートカット、最大60状態のUndo/Redo・ゲームログを担当する。
- 保存形式はschema version 2とし、代表デッキのメイン／サイド枚数から作る署名ごとに`localStorage`へ保存する。同じデッキを開くと保存状態を再開し、「新しい初手」で明示的に置き換える。
- Scryfallのカード情報が取得できなくても、名前と手動レーン移動だけでプレイを継続できる。画像・自動レーン判定・両面情報だけが縮退する。

## アーキタイプ推定

アーキタイプは次の順で決めます。

1. メタゲームページから取得した既知アーキタイプ名と照合する。
2. デッキリストのsubtitleなど、ソース側が持つアーキタイプ名を使う。
3. 日本語圏のデッキ名称辞書と照合する。
4. 正しくラベル付けされたデッキからコアカードを学習し、未分類デッキを再分類する。
5. 残ったデッキを既知アーキタイプ名で再照合する。
6. 土地色と戦略シグナルから大枠ラベルにフォールバックする。

日本語圏で流通するデッキ名は、単なる翻訳ではなく一級のアーキタイプ名として扱います。例: イゼット果敢、イゼット講義、緑単上陸、アゾリウス・モモ。

## 現物候補の判定

候補化するのは、テーブルトップでカード状の現物として置く必要があるものだけです。

- トークン
- 紋章
- 物理的なコピー・トークンやコピー用マーカー
- 裏向き補助
- 計画カードの追跡補助（Plot / Airbend / Paradigm など、除外ゾーンから後で唱えるカードを含む）
- 昼夜マーカー

カウンター類はサイコロ管理で足りるため対象外です。

`copy` という単語がOracleに出ても、すべてコピー・トークン扱いにはしません。`token that's a copy`、`create ... copy`、Offspring など、盤面に置く現物が必要な表現だけを対象にします。

現物ごとの採用デッキ数（deckCount）は全採用デッキURLの和集合で集計し、表示用デッキ一覧の切り詰め（発生源ごと24件、現物ごと36件）と分離します。検索で選んだ同じ母集団を分母・分子に使います。構造化デッキにないカードをページ本文から拾い直す処理は行いません。旧形式の内部呼び出しだけ従来の近似値へフォールバックします。

## 新セット直後の準備

[準備モードの設計・試用手順](new-set-preparation.md)を参照。直前環境の実績を参考資料として残し、新セットの公開カード全体から得た追加候補を別枠に表示します。追加候補を採用率・メタ統計の母集団には混ぜません。

## ログ表示

サーバーログはブラウザへSSEで配信します。検索APIと後追い補完APIは、画面側から渡された検索IDをログに付け、フロントエンドは現在の検索IDに一致するログだけを表示します。

これにより、サーバーを起動しっぱなしにした場合でも、前回検索や別タブの検索ログが現在の検索ログに混ざらないようにします。

ログパネルは初期表示で展開します。検索対象URLの取得状況、キャッシュhit/miss、抽出失敗、ソース枯渇を検索中に確認できることを優先します。

## 外部サービス利用

Scryfall APIは `User-Agent` と `Accept` を付けて呼び出し、検索系エンドポイントは500ms以上の間隔に抑えます。候補カード母集団は24時間キャッシュし、レート制限や一時障害時は期限切れキャッシュがあれば代替使用します。

デッキリスト巡回は公開ページの通常取得だけを対象にします。WAF、Cloudflare、robots.txt、明示的なアクセス制限を回避して巡回しません。

依存方向は起動入口から `app.mjs`、`lib/` へ流し、`lib/` 間の循環を作らない方針です。

現物の集計・チェック保存・後追い補完は `objectKey` を共有する。物理カードはセット＋Oracle ID（未提供なら印刷ID）、仮想補助はセット＋用途名＋タイプで区別する。同じOracle IDの発生源はデッキURLの和集合で集計する。旧形式の物理チェックには仕様の区別がないため、別の版へ推定移行しない。

採用判定では `deck.cards` があれば空配列も含めてそれを正本とする。本文照合はカード配列を持たない旧形式のエントリーだけに限定する。両面カードの情報取得は正式名と各面名を別名として解決し、レスポンスの `requestedName` で依頼名を保持する。ひとり回しのデッキ名と保存識別は変更しない。

トークンの採用集計と画像付きデッキ一覧は全件の `deckUrls` を使い、短い表示用 `decks` と分ける。MTGOの同じページにある複数リストはURLのフラグメントも含めて区別する。選んだデッキのメイン・サイドをそのまま画像表示し、発生源のカードだけを抜粋したリストにはしない。

典型リストの画像は `POST /api/card-metadata` の `language`（`ja` / 既定 `en`）で取得する。英語のcollection結果から正式名を解決し、日本語は同じカードの日本語印刷を照合する。日本語取得で英語キャッシュを上書きしない。UIは6種ずつ日本語画像を取得して進捗を反映し、英語画像への縮退と再取得を提供する。カード画像は表示用であり、選定結果・Arenaコピー・ひとり回しのデッキ識別を変更しない。閉じた後や別デッキに切り替えた後の古い応答は世代番号で破棄する。

初手からのドラッグは、戻すカードが不要な手札から戦場への移動のみキープと一体の状態遷移にする。後手のドローも既存のキープ処理に従い、Undoで初手へ戻せる。マリガン後は戻すカードを選んでキープする必要がある。移動先の表示を変えても、既存のゾーン移動・複数選択・手動操作は共通の状態遷移を使う。

通常検索の `fetchSearchCandidates` は環境データに同梱された24時間以内の候補、通常の候補キャッシュ／再取得を順に使う。再取得も通常キャッシュも利用できない場合のみ、同フォーマットの古い環境候補を警告付きで使う。明示的な更新は引き続き `refresh: true, persist: false` で全取得の成功を要求する。

## 定期メンテナンス（セット発売・禁止改定ごと）

検索品質は次の鮮度依存データに支えられている。新セット発売や禁止改定のたびに確認する。

1. `data/environment-events.json` — 禁止改定とローテーションの履歴。CIは未確認イベントを追記します。検知日の遅れに上限は保証できません。公式本文で適用日とnextAnnouncementDateを確認してください。「変更なし」の発表も手動確認が必要です。
2. `lib/scryfall.js` の候補クエリ — 新メカニズムがカード状の現物や除外追跡を必要とするなら語彙を追加し、`candidateQueryVersion` を上げる。カウンター管理のみのメカニズムは追加しない。
3. `lib/archetype.js` の `archetypeRules` / `archetypeLexicon` — 現行Standardのメタゲームに合わせて更新する（他フォーマットは土地色フォールバックで縮退する設計）。
4. `lib/data.js` の `tokenJapaneseNameMap` と `lib/archetype.js` の `LAND_COLOR_MAP` — 新しいトークン種の和名、新しい2色以上ランドを追加する。

## 自動化

公開本体はSitesのクラウドタスクがGitHub `main`を1時間ごとに確認して更新します。最新の成功公開SHAと一致する場合は何もしません。更新時はテスト・ビルド・認証と保存領域・最新SHAを確認し、同じ公開先へ保存・デプロイします。手順とパスワード変更は[github-deployment.md](github-deployment.md)を参照してください。

`.github/workflows/freshness.yml` が毎朝 06:00 JST に `scripts/freshness-check.mjs` を実行します。

- Scryfall のリーガリティ差分（`banned:{format}` の前回スナップショット比較）から禁止/解禁を検知し、環境イベント表へ自動追記して main へコミットします（`npm test` 通過が条件）。ローテーションで `not_legal` になったカードを「解禁」と誤検知しないよう、現在 `legal` であることを確認してから解禁扱いにします。
- 予告された禁止改定日を過ぎてもイベントが無い場合は Issue を起票します。
- 適用日未確認の禁止改定があれば確認用Issueを起票します。検知日のまま配布先の検索起点に採用しません。
- 新しい通常セットや新キーワードを検知したら `mechanics-audit` ラベルの Issue を起票します。「現物が要るか」の判断は自動化せず、監査（人またはAIエージェント）とPRレビューに委ねます。
- 検知のベースラインは `data/freshness-snapshot.json` に保持し、CIがコミットします。

public リポジトリの scheduled workflow は、リポジトリに60日間活動が無いと自動停止される点に注意してください。

## 変更時のチェック

実装を変えたら、最低限次を確認します。

```powershell
npm test
node --check server.mjs
node --check public/app.js
node --check lib/deck.js
node --check lib/crawl.js
node --check lib/tokens.js
git diff --check
```

触ったファイルに応じて `node --check` の対象は増減します。巡回元やパーサを変えた場合は、[decklist-sources.md](decklist-sources.md) の再測定も行います。API入力境界を変えた場合は、範囲外・不正値・空値が安全な既定値に落ちることも確認します。

`public/app.js` または `public/styles.css` を変更した場合は、`index.html` の読み込みURLにある `?v=` バージョン文字列も必ず更新します。ローカル版を含む既存のブラウザキャッシュに古いファイルが残らないようにします。公開版の認証済み応答には `private, no-store` を付けます。

ブラウザの子モジュールを変更した場合は、そのimport URLの `?v=` も更新します。監査5件のHTTP回帰は `test/audit-api.test.js`、同じデータによる手動UI検証は `node scripts/verify-audit-fixes.mjs` を使います。検証用サーバーは一時ディレクトリと空きポートを使用し、終了時に自身の一時データを削除します。`--cache=stale` / `--cache=missing` で候補サービス停止時の縮退も再現できます。
