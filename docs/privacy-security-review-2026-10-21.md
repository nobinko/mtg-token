# 公開版の個人情報・認証情報の点検（2026-10-21）

対象はToken Finderの公開Worker、配信ファイル、認証・ログ・取得・保存経路、同じコードを使うWindows版です。実在する別利用者の非公開リストを取得する検査、Meleeのアカウント操作は行いません。匿名・独立した2ログイン・合成リスト・通信を差し替えたテストを使用します。

## 発見した問題と修正

| 問題 | 修正 |
| --- | --- |
| ログイン済み全員に検索ログのバッファとライブ更新を配信する実装だった | サーバー検証済みCookieのハッシュで配信を分離。クライアントのrun IDを閲覧権限に使わない。プロセスログを利用者へ配信しない |
| 任意URLの取得と自動転送が可能だった | 対応MTGサイトのHTTPSのみ許可。ホスト完全一致、認証情報・独自ポート・限定公開トークンを拒否。転送先も毎回検証し、POSTは再送しない |
| 共有ページキャッシュに任意URLを保存できた | 検証前の取得・キャッシュ参照を禁止。新しいポリシーで作成したキャッシュだけを再利用 |
| ログアウトでCookieを消しても、そのコピーは期限まで有効だった | D1で失効Cookieのハッシュを記録し、以後のリクエストを拒否。別ログインは維持。開いているログ接続も最大15秒の再検証で終了 |
| 保存済みリスト・ゲームが共用ブラウザーに残ることが分かりにくかった | ログアウト時に保存継続／端末データ削除を選択。削除対象と取り消せないことを表示。IndexedDB・アプリのlocalStorageを明示削除し、対応ブラウザーにはClear-Site-Dataも返す |
| 不正なUnicode署名Cookieで例外が発生した | 署名形式とバイト長を検証し、認証失敗として扱う |
| スクリプトと外部通信の制限が不足していた | CSP、Permissions-Policyを追加。外部へRefererを送らないsame-origin方針を維持。想定外エラーの内部メッセージ・スタックを返さない |
| Honoなどに既知の脆弱性があった | 実行依存を更新し、開発用のesbuild・sharpも修正版へ固定 |

公開情報の表示に必要な選手名・デッキ名は残します。今回の検査で漏えい事故が起きた事実を確認したわけではなく、漏えいにつながり得る実装を修正しました。

## データの保存・送信

- **通常のMelee取得**：公開エンドポイントのみ。MeleeログインCookieや管理者のアカウントを流用しない。
- **本人のMelee API認証**：ブラウザー→このWorker→Melee公式の順に、そのリクエストだけで送信。応答・R2・D1・アプリのログへ保存しない。処理後は入力欄も空にする。実際のAPI資格情報による成功接続は未確認。
- **大会データ**：必要な選手表示名・デッキ名・構成だけを正規化し、取得したブラウザーのIndexedDBへ保存。アカウントのメール等を持ち込むエクスポート項目は除外。大会URLだけでサーバーから他人のリストを開く機能はない。
- **ひとり回し・チェック状態**：ブラウザーのIndexedDB／localStorage。共有パスワードは利用者別アカウントではないため、同じブラウザーを共用する際は退出時に消す。
- **検索ログ**：ログインごとにメモリー内で分離、最大600行・15分まで。ログアウト時に該当バッファを除去。大会モードの内容は記録しない。通常検索でもURLの認証部・クエリーを除き、リクエストのログを標準出力へ出さない。
- **R2**：公開サイトのページ、Scryfallカード情報、環境データ。限定公開URLは対応外。旧ページキャッシュは再取得する。
- **D1**：ログイン試行の回数と期限、失効セッションのハッシュと期限。IPアドレスは秘密鍵付きハッシュで扱う。CookieやAPIシークレットそのものは保存しない。
- **外部サービス**：カード名をScryfallへ照合し、カード画像をScryfall/Wizardsの配信元から読み込む。画像配信元には通常の接続情報（IP等）が伝わる。これら外部へRefererは送らない。Melee公式サイト自身のログインは本アプリのログアウトでは解除しない。
- **ホスティング側の管理ログ**：IP・時刻・User-Agent・URL・HTTP結果が記録される。点検したログではCookieは伏せ字になっており、検査用のPOST本文は含まれていなかった。アプリのSSEとは別の管理者向け記録であり、「個人情報を一切処理しない」という意味ではない。基盤側の保存期間や設定は今回変更していない。

## 検証

- 任意URLの送信前拒否と不正署名について、修正前に回帰テストが失敗することを確認。
- HTTPで異なるセッションのログとリプレイが混ざらないこと、推測したrun ID・scopeで閲覧できないことを確認。
- Worker/D1/R2の結合テスト：匿名拒否、保護された静的ファイル、内部ファイル非公開、2セッションの分離、私的な取り込みのR2非保存、Melee転送拒否、失効Cookie拒否、CSP/キャッシュ制御。
- Nodeの全655テストと公開用Worker検査が成功。依存パッケージ監査は開発用を含め既知の指摘0件。秘密ファイルの追跡混入と代表的な認証情報パターンの検査も成功。
- ローカルの実ブラウザーでログイン→退出の選択→保存データを残したログアウトを確認。Refererを全面禁止した場合のフォームOrigin問題を修正し、CSRF制限を緩めず正規ログインが通ることを確認した。
- 保存データ削除は合成データで検証する。既存利用者の保存済みゲーム・大会を検査のために削除しない。
- [公開v33のHTTP検査記録](evidence/public-privacy-2026-10-21.json)：独立した2ログインで匿名拒否・不正URL拒否・アカウント項目の除外・他セッションからの大会読み出し拒否・失効Cookieを確認した。実画面で保存済みBoros Aggroを再開し、34枚の画像が読めることも確認。
- キャッシュを消した直後の環境検索で約4分後にホスティング側が応答を打ち切ることを確認。巡回は90秒を上限にし、失敗した取得も巡回回数に数える。途中で打ち切った場合は取得済みリストだけの集計であることを明示する。ゲートウェイのHTMLエラーも再試行方法が分かる文面にする。Workerのライブログは他リクエストから直接書き込まず、閲覧側のリクエストから取得して配信する。同じWorkerインスタンス内の一時ログなので、別インスタンスへ割り当てられた検索の途中経過が届かない場合はある。

## 運用上の限界

これは範囲を絞ったコード・設定・通信の点検であり、第三者の侵入テストやホスティング基盤全体の監査ではありません。4桁の共有パスワードは推測に弱いため、第三者への配布を広げる際は長いパスワードへ変更してください。今回の変更では既存のパスワードや公開範囲を変更しません。パスワード変更手順は[公開手順](github-deployment.md)を参照してください。

設計確認の参考：[OWASP SSRF対策](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)、[MDN CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)、[Honoの静的配信修正](https://github.com/honojs/hono/security/advisories/GHSA-5r4p-p66f-jhc7)。
